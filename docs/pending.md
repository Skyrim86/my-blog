## 和谐性诊断（第二次取证，2026-09-23）

问的是「卡片不够好看和谐」。这一轮把 63 个格子按访客真实像素逐格裁下来（`colltiles.py` → `tiles/`），
量各格的明度/彩度，并做了一组「现状 vs 明度归一化」的对拍（`collharmony2.py`）。

量出来的散度（格子实拍，含 CSS 框环；只算卡面那一块）：

| 口径 | 现状 | 明度归一化后（提案近似） |
|---|---|---|
| 卡面平均明度 min / 中位 / max | **76 / 203 / 227** | 147 / 217 / 236 |
| p10 / p90 | 102 / 221 | — |
| 标准差 | **44.0** | 18.1 |
| 彩度 > 40 的卡 | 3 / 63 | — |

- 人物在卡面里的高度占比 0.86~0.98（标准差 0.03）—— **取景是统一的**，问题不在取景比例；
  但**景别**仍混杂（源图本身是特写的仍旧是特写，全身的被裁成胸像），这一条是源图属性，算法归一不了。
- 框环是固定配方 `rgba(255,255,255,.34)`：在 L76 的暗卡上是硬白线，在 L227 的亮卡上几乎看不见 ——
  **同一套框在不同卡面上读数不一致**，这是「不像一套」的第二个来源，且与「低三档分不出」是同一个根。
- 相邻格子明度差 > 70 的有 7 处，最大 186（#59 冷香 223 → #60 初始之音 37，按原画口径）。
- 独立判读（三次、不同取样）结论一致：整墙最大的问题是**明度断层**（暗卡像黑洞、亮卡融进白底，缩略下呈「补丁感」）；
  全局拉齐会明显变整齐，但会把高调卡（#33 银霜、#03 花信）洗成白雾 —— 所以**只能收极端值，不能全局拉平**。

### 「工艺能不能融进 3D 卡」：现状与一次失败的尝试

现状：3D 卡上的工艺只有六个参数（`foil / foilScale / spec / tint / sparkle / edge`），**没有纹样** ——
纹样（和纸、冰裂、星屑、珐琅格、雕花金…）只活在 DOM/CSS 那一层，弹层的 canvas 里看不到。

尝试（`lab/工具/patternproto.py`）：把珐琅格画进**浮雕高度图**（格线抬升 0.055，格 46px），直接改 public 里那张指纹化的
深度图，前后各拍一张对照。结果：**平均绝对差 0.03/255、改动 >3 的像素 0.1%** —— 等于没动。
再加一个夸张对照（把整张高度图抬到 0.85）也只有 0.11/255、0.7% —— 仍然几乎无变化。
但同一次会话里 `stats().relief` 为真（深度纹理已绑）、`relief` 旋钮的对照又明显有响应（上表）。

**所以「工艺进高度图」这条路当时那个『不成立』是误判，2026-09-25 已查清并订正**：
位移旋钮有响应、高度图内容改了没反应，这个「矛盾」的答案是**旧实验改错了文件** ——
`lab/工具/patternproto.py` 把图案写进了 `public/images/cards/depth/*.webp`（构建产物），
而它拍的页面是 `http://127.0.0.1:8831/collection/`，8831 上跑的是 **hugo 开发服务器**，
它从 `assets/` 现渲染 —— 改 `public/` 等于改了一个没人服务的副本，量到的 0.035 就是渲染噪声。
同一个 0.055 幅度 / 46px 格线图案写进**源码**文件后：**卡面内平均绝对差 5.99、>8 的像素 14.65%**
（对照：极端黑白棋盘 20.44 / 48.2%，画面碎成马赛克；噪声底 0.07）。判读同意「表面多了一层格子状起伏、
线条处有高光与阴影」，没有撕裂。

机制（`uDepth` 的采样点）：`hAt()` 直接 `texture2D(uDepth, …)`（TEXTURE1），正面分支
`vFace < 0.5` 走 `parallax()` 的 POM 步进 + 二分细化；顶点里 `p.z += hAt(zuv) * uRelief * …` 做几何起伏，
法线走 `normalFromHeight` 的梯度。**两条路的敏感度差两个数量级**：`uRelief = RELIEF × S.relief × R.relief`
实测只有 0.0684 → POM 位移约 3px（几乎读不出几何），而法线对高频极敏感 ——
所以纹样进 3D 是**靠明暗读出压纹**，与 §八「只改光不改色」同向，不是「几何上真的凸起」。

三条候选路（由低到高）：① 查清后把纹样进高度图（让它成为真的表面起伏）；② 着色器里做程序化纹样，
由 `data/card-styles.yaml` 生成一张 `STYLE_PAT` 表（纹样参数的单一事实源仍在 YAML）；③ 把 CSS 纹样烘进卡面纹理 ——
会复制事实源，不推荐。

### 候选样张轮：纹样家族与幅度（2026-09-25，手工样张，未落管线）

同一个卡（花簪 / 传世 / 烫金箔）、同角度（yaw 0.34 pitch 0.12）、钉档位、卡面内口径、噪声底 0.07。

### 形态重做轮：两档都定案「不做」（2026-09-25）

阈值化遮罩把「人物上不干净」这一条解决掉之后，剩下的是形态本身。三轮重做全被 1:1 判读否掉：

| 轮 | 星芒全息（rays） | 墨染（brush） | 判读 |
|---|---|---|---|
| 1 | 24 条等宽直线 + 3 道完整同心环 → 6 道锥形长芒 + 10 短芒 + 断段弧 + 柔晕 | 等距横扫 → 26 笔随机倾角/断口 | 「仍是几何干扰 / 像 CAD 线框」「仍像数字扫描线」 |
| 2 | 4 道很宽的长芒 + 12 短芒 + 2 道粗弧 + 更紧的中心晕（amp 0.10） | 更少更粗（8 长 + 9 短，笔宽 10~22px）+ 墨团（amp 0.18） | 「偏弱、仍像网/线框」「仍像扫描线、偏弱」 |

**定案：这两档不做浮雕纹样。** 病根不是形态参数调不好，是**和工艺本体的视觉语言冲突** ——
全息卡面本体就是斜向镭射光，再加任何**线状**浮雕都会被读成干扰；墨染卡面本体是水墨画，
线状浮雕读成扫描线。要做的话得换**块面型**形态，或干脆不做（当前选择）。

顺带得到一条可复用的判据：**高频线状/点状形态，加幅度不是杠杆**。数值上这两档已经比
**已通过的参照档**更强（|Δ|>2 的像素：星芒 6.4%、墨染 8.2%，花簪 4.4%），判读仍说「偏弱」——
说明那是形状语义的问题，继续加幅度只会变成更亮的噪点。已写进 `surface-craft-design` §4.5。

另一条：**验证遮罩要离线做**。观星那格判读两次说「人物上仍有线痕」，而离线对比（生成两版到
临时目录、numpy 按区域比）量出主体内的 |Δ| 只有 **0.38/255** —— 人物其实是干净的，判读在这一点上
是锚定错觉。凡是「遮罩有没有生效」这类问题，一律用离线数值裁决，别用判读定罪。
